All three failures, in detail

Every miss belonged to Qwen3.6. Two of them are the same failure mode, and it is worth understanding because it is not a knowledge gap.

cd1 Fibonacci — never produced code runaway reasoning

Asked for a solve(n) returning the nth Fibonacci number, 3.6 hit the 8,192-token cap still thinking, emitting no code block. Suspecting the cap was simply too tight, the task was re-run with a 32,768-token budget. It failed again — finish_reason: length, still no code, after 844 seconds of continuous generation.

Qwen3.632,768 tok · 845s · fail
cd2 Palindrome check — never produced code runaway reasoning

Identical pattern: alphanumeric-only, case-insensitive palindrome test. Capped out at 8,192 tokens, then again at 32,768 after 815 seconds without emitting a function.

Why this isn't a prompt artifact

  • 3.6 solved the other four code tasks — longest increasing subsequence, longest non-repeating substring, interval merging, island counting — using the identical prompt template and extraction logic. The two it failed are the two easiest in the set.
  • Quadrupling the token budget changed nothing, so the cap was not the constraint.
  • Grading ran on the final answer only, with reasoning blocks stripped, and the grader was self-tested against ten hand-written cases before use.

Code tasks were graded by execution: the model's function was extracted, run in a subprocess against hidden test vectors, and scored only if every vector passed. All expected answers — including every maths result — were independently computed before the run rather than assumed.

What this does not prove

Stated plainly, because a benchmark that hides its limits is worth less than one that names them.

  • 47 tasks is a small sample. A 47–44 split is suggestive, not statistically conclusive. The confidence interval on a three-task difference is wide.
  • Qwen3.8 saturated both suites. Scoring 100% means the ceiling was hit — its actual headroom is unmeasured, and the true quality gap could be larger than shown.
  • Runs were sequential, not interleaved. Both models need ~22 GB, so they cannot be co-resident on a 32 GB card. Host load varied between blocks, which adds noise to timing — though not to correctness.
  • Both are 4-bit quantisations, not the original weights. Quantisation damage is not necessarily equal across two different models.
  • Thinking was left at each model's default. Qwen3.8 ships a reasoning-effort control that 3.6 lacks, so part of the token gap is a product decision, not raw capability — but the tokens are spent either way.
  • None of the vendor's headline claims were replicated. The agentic-coding, computer-use and vision benchmarks Qwen reports need harnesses not present here. Vision was not tested at all.
